# 오딘: 발할라 라이징 QA 자동화 - 스모크 테스트 설계

## 목적과 범위

게임 QA 실무에서 빌드마다 반복하던 스모크 테스트를 화면 인식 기반으로 자동화하는 포트폴리오
프로젝트입니다. 범위는 다음 흐름이 정상 동작하는지 확인하는 것으로 한정합니다.

> 게임 실행 → 스플래시 통과 → 캐릭터 선택 화면 → 게임하기 클릭 → 인게임 진입

결과는 실행 1회의 상세 기록인 HTML 리포트와, 여러 실행에 걸친 히스토리인 Google Sheets에
남깁니다.

**범위에서 제외한 것**

- 웹 로그인: 오딘은 웹사이트에서 로그인한 뒤 클라이언트를 실행하는 구조라 클라이언트 안에
  로그인 화면이 없습니다. 웹 로그인까지 자동화하면 계정 비밀번호를 스크립트에 넣어야 하고,
  게임 클라이언트와는 별개 시스템이라 제외했습니다. 로그인이 끝난 상태에서 시작합니다.
- 실제 플레이(사냥, 재화 획득 등)의 자동화

## 제약

- 대상: 오딘: 발할라 라이징 PC 클라이언트 (언리얼 엔진, Windows)
- 안드로이드 단말기가 없어 PC 클라이언트로 진행. 에뮬레이터나 단말은 필요 없습니다.
- 게임 화면은 렌더링된 그래픽이라 pywinauto 같은 일반 Windows UI 자동화로는 요소를 잡을 수
  없습니다. 이미지 인식 방식이 필요합니다.
- 오딘은 안티치트 때문에 관리자 권한으로 실행됩니다. 일반 권한 프로세스의 입력은 Windows
  권한 격리(UIPI)에 막혀 에러 없이 무시되므로, 스크립트도 관리자 권한 터미널에서 실행해야 합니다.
- 클라이언트는 창모드로 실행합니다. 전체화면(exclusive) 모드는 화면 캡처가 안 될 수 있습니다.

## 접근 방식

넷이즈의 게임 QA 자동화 프레임워크 **Airtest**를 사용합니다.

- OpenCV + PyAutoGUI로 직접 구현하는 것보다 학습 곡선이 낮아, 안정적으로 완성하는 데 유리
- 실제 게임업계 QA 자동화에서 쓰이는 툴이라 실무 연결성이 높음

템플릿 이미지 캡처에는 AirtestIDE를 썼지만, 테스트 실행에는 필요하지 않습니다.

## 전체 흐름

1. 실행 중인 오딘 창(`title_re=ODIN`)에 연결
2. 스플래시 로고를 인식하면 클릭. 로딩 중에도 같은 로고가 보여 클릭이 씹히는 경우가 있어서,
   로고가 사라질 때까지 최대 15회 반복 클릭
3. 캐릭터 선택 화면의 고정 제목("캐릭터 선택")이 나타날 때까지 최대 30초 대기
4. "게임하기" 버튼 클릭. 캐릭터 선택 화면을 벗어날 때까지 최대 20회 반복 클릭
5. 인게임 판정용 템플릿 2개가 **모두** 매칭될 때까지 최대 60초 대기
6. 성공/실패와 상관없이 HTML 리포트 생성, Google Sheets에 결과 한 줄 기록

각 단계에서 스크린샷을 찍기 전에 오딘 창을 맨 앞으로 가져옵니다. 다른 창이 겹쳐 찍히는 것을
막기 위해서입니다.

## 판정 기준 설계

화면 인식 자동화에서 가장 중요한 건 "무엇을 템플릿으로 삼을 것인가"였습니다. 원칙은 두 가지입니다.

**계정 상태와 무관하게 항상 같은 모습인 요소만 쓴다.**
캐릭터 선택 화면은 계정마다 보유 캐릭터가 달라 보이는 내용이 다릅니다. 캐릭터 초상화 대신
항상 고정으로 표시되는 화면 제목 텍스트만 템플릿으로 사용해, 누가 어떤 계정으로 돌려도 같은
기준으로 판정되게 했습니다. "게임하기" 버튼도 캐릭터 목록과 무관하게 같은 자리에 있어, 특정
캐릭터를 이미지로 찾을 필요 없이 버튼만 기준으로 다음 단계로 넘어갑니다.

**인게임 진입은 서로 다른 위치의 두 요소가 동시에 보여야 인정한다.**
하나의 아이콘만 보고 판단하면 다른 화면의 비슷한 아이콘을 인게임으로 잘못 인식할 수 있습니다.
그래서 좌상단 **레벨 표시**와 우상단 **상단 메뉴(BM 상점 아이콘 등)** 두 템플릿이 모두 매칭될
때만 성공으로 봅니다. 레벨 표시 템플릿은 주변 요소를 빼고 "레벨" 라벨만 남도록 잘라, 다른
화면과 겹칠 여지를 줄였습니다.

처음 후보로 봤던 하단 상점 아이콘(교환 상인/소모품 상인)은 사냥터에서 스킬 아이콘으로 바뀌는
것을 확인해 제외했습니다. 위치나 퀘스트 상태에 따라 바뀌는 요소는 판정 기준으로 쓰지 않습니다.

## 에러 처리와 리포트

- 단계마다 타임아웃과 재시도 횟수를 두고, 넘기면 어느 단계에서 실패했는지 한글 메시지로 알립니다.
- 실패 시점의 스크린샷을 자동으로 남깁니다.
- Airtest 기본 리포트는 가독성과 디자인이 포트폴리오용으로 부족해, `report.py`에 직접 만든
  리포터로 대체했습니다. 단계별 카드 + PASS/FAIL 배지 + 스크린샷 인라인 표시 구성의 단일 HTML
  파일입니다.
- 실패하면 종료 코드가 0이 아니라 스케줄러나 CI에서 감지할 수 있습니다.

## 실행 이력 관리 (Google Sheets)

HTML 리포트는 실행 1회의 상세 기록이라, 여러 번 돌린 결과를 한눈에 보려면 별도 저장소가
필요했습니다. Google Sheets에 Apps Script 웹 앱을 붙여 웹훅으로 쓰고, 실행이 끝나면 결과 한
줄(시각, PASS/FAIL, 소요시간, 실패 사유)을 POST합니다.

- 설정 파일(`sheets_config.py`)이 없으면 이 단계만 건너뛰고 테스트는 그대로 동작합니다.
- 전송 성공 여부는 HTTP 상태가 아니라 Apps Script가 돌려주는 JSON(`status: ok`)으로 판단합니다.
  배포 권한이 잘못되면 구글 로그인 페이지가 200으로 오기 때문입니다.
- 웹 앱 URL만 알면 누구나 행을 추가할 수 있어, 선택적으로 양쪽에 같은 토큰을 두고 일치하는
  요청만 기록하도록 했습니다.
- 시트 전송이 실패해도 테스트 결과에는 영향을 주지 않습니다.

## 파일 구조

```
QA_AI/
├── smoke_test.air/                    # Airtest 프로젝트 (.air 폴더명과 .py 파일명이 같아야 함)
│   ├── smoke_test.py                  # 메인 테스트 스크립트
│   ├── report.py                      # 커스텀 HTML 리포트 생성기
│   ├── sheets_config.example.py       # Google Sheets 웹훅 설정 예시
│   ├── splash_logo.png                # 템플릿: 스플래시 로고
│   ├── character_select_title.png     # 템플릿: 캐릭터 선택 화면 제목
│   ├── play_button.png                # 템플릿: "게임하기" 버튼
│   ├── ingame_hud.png                 # 템플릿: 인게임 레벨 표시 라벨
│   ├── ingame_topmenu.png             # 템플릿: 인게임 상단 메뉴 (BM 상점 아이콘 등)
│   └── log/                           # 실행 시 자동 생성 (스크린샷, report.html)
├── docs/
│   ├── google_apps_script.js          # Google Sheets 쪽 수신 코드
│   └── screenshots/                   # README용 스크린샷
├── requirements.txt
└── README.md
```

계정 정보 파일은 두지 않습니다. 로그인이 끝난 상태를 전제로 하므로 스크립트가 계정 정보를 다룰
일이 없습니다.

## 설계 변경 이력

구현하면서 처음 설계와 달라진 부분입니다.

- **범위 확장 — 캐릭터 선택 화면까지 → 인게임 진입까지.** 처음에는 캐릭터 선택 후 진입은
  계정마다 보유 캐릭터가 달라 재현성이 떨어진다고 보고 제외했으나, "게임하기" 버튼이 캐릭터
  목록과 무관하게 고정 위치라는 것을 확인하고 인게임 진입까지 넓혔습니다.
- **로그인 단계 삭제.** 클라이언트 안에 로그인 화면이 있을 것으로 보고 계정 설정 파일까지
  만들어 뒀으나, 웹 로그인 구조임을 확인하고 관련 파일과 단계를 모두 제거했습니다.
- **리포트 — Airtest 기본 리포트 → 직접 만든 리포터.** Airtest를 고른 이유 중 하나가 리포트
  자동 생성이었는데, 실제로 보니 포트폴리오용으로는 부족해 `report.py`로 대체했습니다.
- **인게임 판정 앵커 교체.** 하단 상점 아이콘 → 사냥터에서 바뀌는 것을 확인 → AUTO 버튼 →
  상태에 따라 불안정 → 최종적으로 레벨 표시 + 상단 메뉴 두 개로 확정.
- **폴더 구조.** `templates/` + `scripts/` 분리 구조로 시작했으나, Airtest의 `.air` 규칙(폴더명과
  스크립트명이 같아야 함)에 맞춰 `smoke_test.air/` 하나로 합쳤습니다.
- **Google Sheets 연동 추가 (2026-09-16).** 실행 히스토리를 남기기 위해 구현 후 추가했습니다.
- **템플릿 캡처 방식.** AirtestIDE의 Devices 패널이 창 목록을 비워 보이고 오래된 창 핸들을
  캐싱하는 문제가 있어, 패널 대신 스크립트에서 `snapshot()`으로 전체 화면을 찍고 Pillow로
  잘라내는 방식으로 템플릿을 만들었습니다.

## 자동화 스크립트 자체의 검증

- 템플릿 이미지가 실제 화면과 매칭되는지 수동으로 1차 확인
- 템플릿 파일명을 일부러 없는 파일로 바꿔 실행해, 실패 시에도 FAIL 배지와 실패 스크린샷이 담긴
  리포트가 생성되는지 확인
- 여러 번 반복 실행해 화면 밝기·그래픽 설정 차이로 인한 오탐이 없는지 점검

## 향후 확장

지금의 연결·리포팅 구조를 재사용해 같은 오딘 프로젝트 안에서 시나리오를 늘려갈 계획입니다.

- 인게임 메뉴 진입/복귀 검증 (상단 메뉴 → 각 화면 진입 확인 → 닫고 HUD 복귀 확인)
- 이미지 비교 기반 UI 회귀 테스트
- 특정 버그 재현 자동화
- 다른 게임/플랫폼은 별도 프로젝트로 분리
