# 시나리오 확장 구조와 상단 메뉴 테스트 설계

## 목적

스모크 테스트 하나뿐이던 프로젝트를 테스트를 여러 개 담을 수 있는 구조로 바꾸고, 그 위에 두 번째
테스트인 **상단 메뉴 진입/복귀 테스트**를 올립니다. 앞으로 설정 메뉴 같은 다른 인게임 기능 테스트도
같은 방식으로 추가합니다.

## 바꾸기 전의 문제

`smoke_test.py` 한 파일에 역할이 다른 코드가 섞여 있었습니다.

| 코드 | 역할 |
|---|---|
| 오딘 창 찾기, 연결, 창 앞으로 가져오기, 스크린샷 | 어떤 테스트든 똑같이 필요 |
| 스플래시 → 캐릭터 선택 → 게임하기 → 인게임 | 스모크에서는 검증 대상이지만, 다른 테스트에서는 시작 전에 갖춰야 할 조건 |
| 리포트 만들기, 시트 전송, 에러 메시지 한글화 | 어떤 테스트든 똑같이 필요 |
| 실행하고 결과 정리하는 부분 | 어떤 테스트든 똑같이 필요 |

두 번째 테스트를 만들려면 이 파일을 통째로 복사해야 했습니다.

## 검토한 방식

- **스모크 뒤에 이어 붙이기** — 스모크가 끝없이 길어지고, 중간에 실패하면 뒤를 못 봅니다. 메뉴만
  따로 돌릴 수도 없습니다. "가장 빠르게 실행 여부만 거른다"는 스모크 테스트의 의미가 사라집니다.
- **완전히 별도 스크립트** — 인게임 진입 코드를 복사하거나, 사람이 미리 인게임까지 들어가 놓아야
  합니다. 후자는 "누가 언제 돌려도 같은 결과"라는 원칙에 어긋납니다.
- **공통 부품 + 테스트 분리 + 실행 파일 하나 (채택)** — 인게임 진입 코드를 한 곳에 두고, 스모크는
  그것을 *검증*하고 메뉴 테스트는 *시작 조건*으로 씁니다. 실행하고 결과를 정리하는 부분도 하나만
  둡니다.

## 구조

```
odin_qa/                       # smoke_test.air 에서 이름 변경
├── run.py                     # 실행 파일: python run.py smoke | top_menu | all
├── core/                      # 공통 부품
│   ├── client.py              # 오딘 창 찾기·연결·스크린샷·템플릿 이미지 불러오기
│   ├── flows.py               # 게임 조작: 스플래시 통과, 인게임 진입, 메뉴 열기/닫기
│   ├── context.py             # 테스트 한 번 실행의 단계·항목·결과 기록
│   ├── errors.py              # 실패 단계 구분, 에러 메시지 한글화
│   ├── reporter.py            # HTML 리포트
│   └── sheets.py              # Google Sheets 전송
├── scenarios/                 # 테스트 하나에 파일 하나
│   ├── smoke.py
│   └── top_menu.py
├── templates/
│   ├── common/                # 스플래시 로고, 캐릭터 선택 제목, 게임하기 버튼, 인게임 판정용 2장
│   └── top_menu/              # 메뉴마다 아이콘 1장 + 열린 화면 1장
├── tools/                     # 템플릿 만들 때 쓰는 캡처/자르기 도구
└── log/                       # 실행 시 자동 생성
```

`.air`라는 폴더 이름은 Airtest가 제공하는 리포트 명령을 쓸 때만 필요한 규칙입니다. 리포트를 직접
만들어 쓰고 있어서 이 규칙은 필요 없어졌고, 테스트가 여럿 들어가는 폴더에 `smoke_test.air`라는
이름은 헷갈려서 `odin_qa/`로 바꿨습니다.

## 각 부분이 하는 일

**시나리오 파일**은 "무엇을 확인하는가"만 적습니다. 연결, 스크린샷, 리포트, 시트는 전혀 신경
쓰지 않습니다.

```python
# scenarios/top_menu.py
MENUS = [
    ("event", "이벤트"),
    ("gift", "선물"),
    ("shop", "BM 상점"),
    ("bag", "가방"),
    ("menu", "메뉴"),
]

def run(ctx):
    flows.ensure_ingame(ctx)                  # 인게임이 아니면 자동으로 들어감
    for key, label in MENUS:
        with ctx.case(label):                 # 메뉴 하나가 실패해도 다음 메뉴는 계속
            flows.open_menu(ctx, key, label)
            flows.close_menu(ctx, key, label)
        flows.recover_ingame(ctx)             # 메뉴가 열린 채 남았으면 ESC로 복구
```

메뉴가 늘어나면 `MENUS`에 한 줄 추가하고 템플릿 이미지 두 장(`<key>_icon.png`, `<key>_opened.png`)을
넣으면 됩니다. 코드는 바뀌지 않습니다.

**flows.py**는 게임 화면을 다루는 동작을 모아둔 곳입니다. 스모크의 `pass_splash`(스플래시 통과),
`enter_game`(인게임 진입)은 원래 코드를 그대로 옮긴 것이고, 메뉴 테스트를 위해 넷을 추가했습니다.

- `ensure_ingame` — 인게임 상태를 보장합니다. 이미 인게임이면 아무것도 안 하고, 스플래시나
  캐릭터 선택 화면이면 인게임까지 들어갑니다. 어느 화면도 아니거나 들어가다 실패하면 "사전 조건"
  실패로 기록합니다. 인게임 진입은 이 테스트가 확인하려는 것이 아니기 때문입니다.
- `open_menu` — 아이콘을 누르고 그 메뉴 화면이 나타날 때까지 기다립니다. 아이콘을 못 찾으면
  "조작" 실패, 눌렀는데 메뉴 화면이 안 나오면 "화면 확인" 실패입니다.
- `close_menu` — ESC를 누르고, 메뉴 화면이 사라지고 인게임 화면(HP/MP 바 + 상단 메뉴)이 돌아올
  때까지 기다립니다. 둘 다 확인하는 이유는 햄버거 메뉴처럼 인게임 화면 위에 겹쳐 뜨는 메뉴가
  있어서입니다. 오딘 메뉴는 ESC로 닫히는 것을 확인했고, 안 닫히는 메뉴가 나오면 그 메뉴만 뒤로가기
  버튼 템플릿을 추가하면 됩니다.
- `recover_ingame` — 메뉴 하나가 실패해서 화면이 열린 채 남았을 때, 다음 메뉴가 연달아 실패하지
  않도록 ESC를 최대 3번 눌러 인게임 화면으로 돌아가 봅니다.

**context.py**는 테스트 한 번 실행의 기록입니다. 단계를 남기고, 스크린샷을 찍고, `case`로 메뉴
하나하나의 성공/실패를 따로 기록합니다. 메뉴 하나에서 문제가 나면 그 메뉴만 실패로 적고 다음
메뉴로 넘어갑니다. 테스트 전체는 모든 메뉴가 통과했을 때만 PASS입니다.

**run.py**는 유일한 실행 파일입니다. 오딘 창 확인 → 연결 → 요청한 테스트를 순서대로 실행 →
테스트마다 리포트 하나와 시트 한 줄 → 하나라도 실패하면 종료 코드 1. `all`로 돌릴 때 스모크가
실패하면 뒤 테스트는 실행하지 않고 "사전 조건" 실패로 기록합니다. 스모크가 깨졌는데 메뉴를
시도하는 건 의미가 없어서입니다.

## 실패 단계 구분

실패했을 때 "어디서" 실패했는지를 네 가지로 나눠 기록합니다.

| 단계 | 뜻 | 예 |
|---|---|---|
| 실행 준비 | 테스트를 시작조차 못 함 | 오딘 창이 없음, 두 개 켜져 있음, 관리자 권한이 아님 |
| 사전 조건 | 테스트의 시작 조건이 안 갖춰짐 | 메뉴 테스트인데 인게임 진입 실패 |
| 조작 | 눌러야 할 것을 못 찾음 | 아이콘이 화면에 없음 |
| 화면 확인 | 눌렀는데 기대한 화면이 아님 | 메뉴 화면이 안 뜸, ESC 후 인게임 화면으로 안 돌아옴 |

Airtest나 Windows 쪽에서 나는 에러(영어 원문)는 한글 설명으로 바꿔서 기록하고, "실행 준비"로
분류합니다.

## 리포트와 시트

- HTML 리포트: 테스트마다 `log/<이름>_report.html`. 메뉴 테스트는 메뉴 하나가 카드 하나입니다.
- Google Sheets: `실행 시각 | 시나리오 | 결과 | 소요시간(초) | 실패 단계 | 실패 사유`. 테스트가
  여럿이어도 한 시트에 쌓고 시나리오 열로 구분합니다. 메뉴별 실패는 `선물: 선물 아이콘을 눌렀지만
  10초 안에 선물 화면이 나타나지 않았습니다`처럼 메뉴 이름을 앞에 붙여 한 칸에 모읍니다.

## 템플릿 이미지 원칙

- 계정, 장소, 시간에 따라 바뀌지 않는 부분만 씁니다. 메뉴가 열렸는지는 그 메뉴 화면의 제목처럼
  내용과 상관없는 부분으로 판단합니다. 이벤트 배너, 상점 상품, 가방 속 아이템은 쓰지 않습니다.
- 빨간 알림 점이 붙는 아이콘은 점이 들어가지 않게 잘라서, 알림이 있든 없든 똑같이 인식되게 합니다.
- 뒤가 비치는 반투명 요소는 쓰지 않습니다. 위치가 고정이어도 뒤 배경이 바뀌면 인식이 깨집니다.
  인게임 판정에 쓰던 "레벨" 글자가 이 문제로 실패해서 HP/MP 바(뒤가 비치지 않는 단색)로
  바꿨습니다. 자세한 건 README의 "구현 중 발견한 문제" 참고.

## 단위 테스트

자동화 코드 자체도 pytest로 검증합니다. 오딘 없이 돌아가는 부분(에러 분류, 메뉴별 결과 집계, 시트
전송 판정, 인게임 진입 분기, 메뉴 열기/닫기 분기, 실행 순서와 차단 규칙)을 43개 테스트로
확인합니다. 코드를 고칠 때마다 게임을 켜지 않고도 로직이 깨지지 않았는지 알 수 있습니다.

## 범위 밖

- 햄버거 메뉴 안의 항목 약 20개 — 구조가 안정된 뒤 `MENUS`에 추가하는 방식으로 확장합니다.
