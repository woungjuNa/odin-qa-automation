# 오딘: 발할라 라이징 QA 자동화 - 스모크 테스트 (Phase 1) 설계

## 목적

게임 QA 이직 포트폴리오용 프로젝트. 실제 MMORPG QA 경력(PC/AOS/iOS 동시 서비스 모바일 MMORPG)과
연결되는, 화면 인식 기반 게임 자동화 시스템을 구축한다.

Phase 1의 범위는 **스모크 테스트**로 한정한다: 게임 실행 → 스플래시 통과 → 캐릭터 선택 화면
→ 게임하기 클릭 → 인게임 진입까지 정상 동작하는지 자동으로 검증하고, 결과를 리포트로 남긴다.

(최초에는 캐릭터 선택 화면까지만 확인하는 것으로 범위를 잡았으나, "게임하기" 버튼이 캐릭터
목록과 무관하게 항상 같은 위치에 고정으로 있어 특정 캐릭터를 골라야 하는 문제 없이 클릭할 수
있다는 걸 확인하고 인게임 진입까지 확장했다.)

(오딘 PC 클라이언트는 로그인을 웹사이트에서 먼저 처리한 뒤 게임을 실행하는 구조라, 클라이언트
내부에 별도 로그인 화면이 없음을 구현 중 확인했다. 웹 로그인 자동화는 실제 계정 비밀번호를
자동화 스크립트에 노출시켜야 해서 보안 부담이 크고, 게임 클라이언트와는 별개 시스템이라
Phase 1 범위에서 제외한다.)

## 배경 / 제약

- 대상 게임: 오딘: 발할라 라이징 (언리퀄 엔진 기반, 카카오게임즈 PC 클라이언트)
- 안드로이드 단말기 보유하지 않음 → PC 클라이언트로 테스트 (에뮬레이터/단말 불필요)
- 게임 화면은 렌더링된 그래픽이라 일반 Windows UI 자동화(pywinauto 등)로 요소를 인식할 수 없음
  → 이미지 인식 기반 자동화가 필요
- 담당자 코딩 경험: 약 3년 전, 프론트엔드(HTML/CSS) 위주. 로직 중심 프로그래밍 경험은 적음
- 코딩 관련 개발 환경(Python, 에디터 등) 미설치 상태 → 처음부터 설치 안내 필요
- 오딘은 안티치트 때문에 관리자 권한으로 실행됨 → 자동화 스크립트도 관리자 권한 터미널에서
  실행해야 함 (Windows 권한 격리(UIPI)로 인해, 일반 권한에서는 마우스 클릭이 조용히 실패함)

## 접근 방식

**Airtest** (넷이즈의 게임 QA 자동화 오픈소스 프레임워크)를 사용한다.

이유:
- 이미지 매칭 기반 자동화를 직접 구현(OpenCV+PyAutoGUI)하는 것보다 학습 곡선이 낮아,
  코딩 공백이 있는 상태에서도 완주 가능성이 높음
- 실제 게임업계 QA 자동화 현장에서 쓰이는 툴이라 "실무 툴 활용 경험"으로 포트폴리오에 어필 가능
- 실행 결과를 HTML 리포트(단계별 스크린샷 포함)로 자동 생성 → 별도 리포팅 기능 구현 불필요

## 전체 흐름

1. 오딘 PC 클라이언트 실행 상태에서 시작 (계정 로그인은 사용자가 미리 완료해둔 상태)
2. 인트로/스플래시 화면 통과 (로고 이미지 매칭 후, 화면이 실제로 넘어갈 때까지 반복 클릭 —
   로딩 중에는 같은 로고가 보여도 클릭이 씹히는 경우가 있어서)
3. 캐릭터 선택 화면 진입 대기 → 캐릭터 목록과 무관하게 항상 고정으로 표시되는 화면 제목
   ("캐릭터 선택") 요소 인식 성공 시 다음 단계로 (캐릭터 초상화 등 계정별로 달라지는
   요소는 템플릿으로 사용하지 않음 — 재현 가능성을 위해)
4. "게임하기" 버튼 클릭 (캐릭터 목록과 무관하게 항상 같은 위치에 고정으로 있어, 특정
   캐릭터를 선택할 필요 없이 현재 선택된 캐릭터로 바로 진행)
5. 인게임 진입 확인 → 위치·퀘스트 상태와 무관하게 항상 고정으로 있는 두 UI 요소
   (AUTO 버튼, 상단 다이아몬드/설정 메뉴 아이콘)가 **모두** 인식되면 "성공"으로 판정
   (하단 상점 아이콘은 사냥터에서는 스킬 아이콘으로 바뀌는 걸 확인해 템플릿에서 제외)
6. 결과 기록 및 커스텀 HTML 리포트 생성

## 구성 요소 및 파일 구조

```
QA_AI/
├── smoke_test.air/                    # Airtest 프로젝트 규칙 (.air 폴더명과 동일한 .py)
│   ├── smoke_test.py                  # 메인 테스트 스크립트
│   ├── report.py                      # 커스텀 HTML 리포트 생성기
│   ├── splash_logo.png                # 템플릿: 스플래시 로고
│   ├── character_select_title.png     # 템플릿: 캐릭터 선택 화면 고정 타이틀
│   ├── play_button.png                # 템플릿: "게임하기" 버튼
│   ├── ingame_hud.png                 # 템플릿: 인게임 AUTO 버튼
│   ├── ingame_topmenu.png             # 템플릿: 인게임 상단 다이아몬드/설정 메뉴
│   └── log/                            # 실행 시 자동 생성 (로그/스크린샷/리포트)
├── requirements.txt
├── .gitignore
└── README.md                           # 프로젝트 설명 (포트폴리오 핵심 문서)
```

- Airtest CLI 리포트 생성 기능이 정상 동작하려면 `.air` 폴더명과 그 안의 `.py` 파일명이 같아야
  해서, 최초 설계의 `templates/` + `scripts/` 분리 구조 대신 이 규칙을 따른다 (구현 단계에서 조정)
- **smoke_test.py**: Airtest의 `touch()`, `wait()`, `exists()` 등으로 전체 흐름을 구현
- 계정 정보 파일은 두지 않는다 — 로그인은 클라이언트 실행 전 웹사이트에서 끝나 있는 상태를
  전제로 하므로, 스크립트가 계정 정보를 다룰 필요가 없음

## 에러 처리 & 리포트

- 각 단계마다 타임아웃 설정 (예: 화면 요소를 정해진 시간 내 못 찾으면 실패 처리)
- 실패 시점 스크린샷 자동 저장
- 각 단계 진행 상황을 기록 (예: "스플래시 화면 클릭 시도")
- Airtest 기본 리포트는 가독성·디자인이 부족해 포트폴리오용으로는 직접 만든 리포터
  (`report.py`)로 대체 — 단계별 카드 UI + 색상 배지(PASS/FAIL) + 스크린샷 인라인 표시
- 스크린샷 촬영 전 항상 오딘 창을 맨 앞으로 가져와, 다른 창이 겹쳐 찍히지 않도록 함

## 향후 확장 (Phase 1 범위 밖)

- 반복 작업 검증 (일일퀘스트, 사냥터 이동, 자동전투 등 시나리오 후 상태 체크)
- UI 회귀 테스트 (이미지 비교 기반)
- 특정 버그 재현 자동화
- 플랫폼 확장: 니케 등 다른 게임, 또는 iOS/Android
- 심화: Airtest 대신 OpenCV/PyAutoGUI로 직접 구현해보며 기술 이해도 심화

## 테스트 방법 (자동화 스크립트 자체의 검증)

- 템플릿 이미지가 실제 게임 화면과 정확히 매칭되는지 수동으로 1차 확인
- 여러 번 반복 실행하여 화면 밝기/그래픽 설정 차이로 인한 오탐(false positive/negative) 여부 점검
